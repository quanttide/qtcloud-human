# 邮件：量潮人事云项目说明

**主题：量潮人事云项目说明与使用入口**

各位同事：

下面是量潮人事云（QtCloud HR / `qtcloud-human`）项目的整体说明，方便大家快速了解项目定位、当前能力和使用方式。

## 一、项目定位

量潮人事云是面向人力资源业务的工作台，目标是把招聘、培训、绩效、薪酬和员工关系等信息放到同一套业务视图中，形成“计划—执行—记录—评估”的闭环。

当前仓库同时承载：

- Flutter 工作台：面向业务人员的跨平台前端；
- Go provider：对外提供 HTTP API，并承接招聘业务动作；
- Rust CLI：提供招聘计划和岗位查询等命令行能力；
- `qtrecurit` 子模块：提供招聘邮件读取、报告生成和招聘沟通动作；
- Terraform 与 GitHub Actions：负责阿里云函数计算、OSS/CDN 和发布流程；
- 示例代码：用于验证人事 API 和招聘计划数据契约。

## 二、工作台模块

工作台左侧目前包含七个模块：

| 模块 | 当前作用 |
|------|----------|
| 总览 | 聚合各模块指标和最新动态 |
| 计划 | 展示招聘、培训、绩效、薪酬等计划及进度 |
| 招聘 | 读取候选人、生成报告、人工审核、执行招聘沟通动作和查看简历 |
| 培训 | 展示培训主线任务和带教反馈 |
| 绩效 | 展示行为成果、参考指标和评估结果 |
| 薪酬 | 按有效工时和职级时薪展示结算结果 |
| 关系 | 展示入职、试用期、晋升、离职等员工生命周期记录 |

需要特别说明：目前只有招聘模块已经接入 provider API；总览、计划、培训、绩效、薪酬和关系页面仍主要使用 `src/studio/assets/mock/` 下的演示数据，后续再逐步替换为真实 API。

## 三、招聘闭环

招聘模块是当前最完整的业务链路：

1. 从 HR 邮箱同步新投递邮件；
2. 将候选人快照保存到 provider 的运行时状态；
3. 在工作台查看邮件主题、正文、岗位和简历附件；
4. 人工将候选人标记为“通过”或“拒绝”；
5. 生成招聘统计报告；
6. 对候选人执行发送问卷、发送实训邀约、发送笔试或生成面试通知；
7. 手动预览或下载简历；
8. 将操作元数据写入审计日志。

所有真实招聘动作默认关闭，页面默认使用 `dry_run`。真实读信、发信和简历下载只有在认证、写权限、provider 环境检查和部署开关全部满足时才会执行。

## 四、系统架构

整体调用链如下：

```text
浏览器 / Flutter Studio
        |
        v
统一 API 网关与认证
        |
        v
Go provider
        |
        v
qtrecurit adapter
        |
        +--> lark-cli / HR 邮箱
        +--> 简历缓存
        +--> 候选人状态
        +--> 招聘审计日志
```

生产环境中，Flutter Web 静态资源发布到阿里云 OSS，并通过 CDN 提供访问；provider 以阿里云函数计算 FC custom-container 运行。`qtrecurit`、`lark-cli` 和 `curl` 会被打包进 provider 镜像。

## 五、如何使用

生产工作台入口：

```text
https://human.cloud.quanttide.com/
```

首次进入后先完成统一认证，再进入招聘页面。推荐操作顺序：

1. 点击“检测环境”，确认 `qtrecurit` 和 HR 邮箱状态正常；
2. 保持 `dry_run` 打开，点击“拉取新邮件”验证同步链路；
3. 点击“生成报告”验证报告链路；
4. 选择候选人，查看人工审核和简历预览；
5. 只有在确认生产配置和候选人无误后，才考虑关闭 `dry_run` 执行真实动作。

项目级完整使用、开发和部署说明见：

```text
docs/user-guide.md
```

## 六、代码入口

```text
src/studio/                 Flutter 工作台
src/provider/               Go API 服务
src/cli/                    Rust CLI
third_party/qtrecurit/      招聘 CLI 子模块
manifests/terraform/        阿里云基础设施代码
examples/                   参考实现和数据契约示例
```

常用本地验证命令：

```bash
cd src/provider && go test ./...
cd src/cli && cargo test
cd src/studio && flutter test
```

## 七、当前边界

- 非招聘模块目前以 mock 数据和页面模型为主，不能当作真实业务数据源；
- provider 的真实招聘动作默认关闭；
- HR 邮箱认证态必须在 Linux/FC 等价环境建立，不能直接把 Windows 本机凭证复制到生产容器；
- 前端必须访问 API 网关地址，不能绕过网关直接访问 FC HTTP 触发器；
- 候选人、简历和审计数据属于敏感数据，生产凭证和私有 OSS 前缀不能提交到 Git。

## 八、协作方式

本仓库是 `quanttide-platform` 的子模块。提交时需要执行两段式流程：

1. 在 `qtcloud-human` 子仓库提交并推送；
2. 回到主仓库更新子模块引用并提交推送。

如需新增业务模块，建议遵循：

```text
BRD → PRD → ADD → 代码 → QA
```

如有接口、数据模型或部署配置变更，请同步更新使用文档和变更记录。
