# 员工关系页面规划

这个页面的主体是**员工生命周期记录**：管理入职、试用期、调动、晋升、降职、离职等员工关系事件。员工状态明确、事件可回溯，试用期是筛选与培训的延续。

## 内容原则

- **生命周期全记录**：入职、试用期、调动、晋升、降职、离职——一类事件一条记录
- **状态明确**：当前雇佣状态（试用期中/正式/离职）与关键日期清晰
- **试用期是筛选的延续**：试用期主线任务与培训/绩效记录互为印证，转正以验收为准
- 晋升/降职以绩效与培训验收为依据，事件可回溯

## 入口与鉴权

- 入口：工作台员工关系入口，面向员工本人、HR
- 鉴权：员工查看自己的状态与记录；HR 维护生命周期事件
- 事件确认后归档，离职走交接流程

## 页面结构

### 关系头部区

- 员工：姓名、身份（岗位/职级）
- 当前状态：状态徽标（试用期中/正式/离职）与关键日期（入职日、试用期结束）

### 生命周期记录区（主体）

- 事件条目：事件类型（入职/试用期/调动/晋升/降职/离职）、标题、时间、状态
- 事件与培训/绩效记录对应：试用期任务、转正评估互为印证

### 状态说明区

- 当前阶段说明：试用期要点与下一步（转正评估/离职交接）
- 离职交接要求：交接文档、复盘、接手人评审

## 组件明细

| 组件 | 使用位置 |
|------|---------|
| 关系头部卡 | 页面顶部（员工、状态徽标、关键日期） |
| 生命周期事件条目 | 记录区（类型徽标、标题、时间、状态） |
| 状态说明卡 | 说明区（当前阶段、下一步） |

## 数据与契约

- `employee_relation`：员工关系聚合（员工、当前状态、入职日、试用期、事件链）
- `relation_record`：生命周期事件（类型、标题、时间、状态）——页面主体
- 事件类型枚举：`onboard` / `probation` / `transfer` / `promotion` / `demotion` / `resignation`

## 边界条款

- 试用期是筛选的延续，转正以主线任务验收为准
- 晋升/降职以绩效与培训验收为依据，不做无依据调整
- 离职须完成交接文档、复盘与接手人评审
