# 绩效页面规划

这个页面的主体是**绩效记录展示**：展示一个人在一段绩效周期里实际做了什么——行为成果记录（时间、事项、结果），与前台结果对齐，事实可回溯。围绕职级制度运行，考核标准与职级等级挂钩，按职级序列区分侧重。

## 内容原则

- **主体是行为成果**：这个人在绩效周期里做过什么（时间、事项、结果）——与前台结果对齐，同一份记录、同一种展示
- **围绕职级制度**：考核标准与职级等级挂钩，职级越高要求越高；初级岗位关注具体行动，高级岗位关注最终结果
- **指标仅作参考**：数字资产贡献（GitHub、Figma 等）统计可作为参考指标，但不是唯一或主要指标
- 评估结论基于行为成果记录，可回溯

## 入口与鉴权

- 入口：工作台绩效入口，面向员工本人、直属上级、HR
- 鉴权：员工可查看自己的记录；上级可评估下属；HR 管理周期与等级评定
- 记录仅评估相关人可见，评估结束后归档

## 页面结构

### 绩效头部区

- 员工：姓名、身份（岗位/职级）
- 绩效周期：考核周期（月度/季度/年度）、周期状态

### 行为成果记录区（主体）

- 历史行为：这段周期里做过哪些事情（时间、事项、结果）——事实可回溯
- 实战/任务记录：连续多日任务执行（任务、过程、结果）
- 与前台结果对齐：同一份 `record` 契约，后台展示、前台展示同构

### 参考指标区

- 数字资产贡献统计（GitHub、Figma 等看板与 API 数据），标注为参考指标，不唯一不主要

### 评估结果区

- 绩效等级评定：依据行为成果记录与职级标准评定等级
- 评估评语：评估者署名；面谈记录与改进计划

## 组件明细

| 组件 | 使用位置 |
|------|---------|
| 绩效头部卡 | 页面顶部（员工、身份、绩效周期） |
| 行为成果记录条目 | 记录区（时间、事项、结果） |
| 任务记录条目 | 记录区（任务、过程、结果） |
| 指标看板卡 | 参考指标区（数字资产贡献统计） |
| 评估结果卡 | 评估区（等级、署名评语、面谈） |

## 数据与契约

- `record`：行为成果记录（时间、事项、结果）——页面主体，与前台展示同构
- `cycle`：绩效周期（周期、阶段状态）
- `metric`：参考指标（数字资产贡献统计，仅参考）
- `assessment`：评估（评估者、等级、评语）

## 边界条款

- 指标仅作参考，不作为唯一或主要依据
- 考核标准围绕职级等级，按职级序列区分侧重
- 评估基于行为成果记录，结论可回溯、可申诉
