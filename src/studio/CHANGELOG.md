# CHANGELOG

## [0.1.0-alpha.16] - 2026-09-13

### Changed

- 招聘页增加外发动作确认，区分演练预览与真实发送，避免误触发真实招聘动作。
- 已拒绝候选人支持重新进入人工审核，窄屏工作区改为收件箱与详情上下布局。
- 运维功能从右上角菜单展开为横向操作区，直接展示检测环境、拉取新邮件和生成报告。

## [0.1.0-alpha.15] - 2026-09-12

### Changed

- 动作区改为三态：待处理只显示“通过 / 拒绝”，已通过只显示流程动作，已拒绝不再显示任何发送按钮，只保留筛选依据。
- 右栏把决定与动作提到候选人标题下方，不再被邮件正文和简历附件压在中间。
- `dry_run` 从顶栏英文开关改为动作区横幅，关闭时提示“真实发送已开启”。
- 顶栏的检测环境、拉取新邮件和生成报告收进“运维”菜单；招聘统计去掉彩色数字块并补上分母。
- 收件箱列表改为一行状态文字，终态加左侧色条，不再平铺多枚彩色标签。

## [0.1.0-alpha.14] - 2026-09-08

### Fixed

- 将招聘统计中的“未自动处理”改为“待处理”，准确表达需要人工处理的邮件。

## [0.1.0-alpha.13] - 2026-09-08

### Fixed

- Word 简历只显示下载按钮，不再显示 PDF 专用的预览按钮；PDF 预览行为保持不变。

## [0.1.0-alpha.12] - 2026-09-08

### Fixed

- 修复 PDF 简历预览 iframe 挂载时序问题，确保预览内容绑定到当前页面。

## [0.1.0-alpha.11] - 2026-09-07

### Fixed

- 预览简历时先读取二进制内容并在当前页面内嵌显示，不再被网关的附件响应头触发下载。
- “预览”和“下载”动作分离，点击预览不会再调用下载操作。

## [0.1.0-alpha.10] - 2026-09-07

### Fixed

- 简历下载改为当前页面直接触发，不再打开空白新窗口。
- 简历预览生成后不再自动复制带访问令牌的临时链接到剪贴板。

## [0.1.0-alpha.9] - 2026-09-07

### Added

- 招聘页 provider 状态栏显示当前已认证账号编号，便于确认真实动作使用的账号。

## [0.1.0-alpha.8] - 2026-09-07

### Fixed

- 登录保存并恢复 refresh token，访问令牌过期后刷新页面会自动续期。
- refresh token 失效时清理旧登录态并回到登录页，避免工作台显示后持续提示认证失败。

## [0.1.0-alpha.7] - 2026-09-06

### Added

- 新增统一认证登录页，招聘 API 使用当前登录用户的 Bearer Token。
- 生产 API 基址支持 `api.quanttide.com/qtcloud-human` 网关前缀，简历预览链接保持网关路径。

## [0.1.0-alpha.6] - 2026-09-06

### Fixed

- 首次手动下载会在点击事件内预先打开临时窗口，避免异步生成下载链接时被浏览器弹窗拦截。
- 使用说明明确当前匿名 provider 入口不能作为正式身份认证，真实招聘动作保持关闭。

## [0.1.0-alpha.5] - 2026-09-06

### Changed

- 取消候选人切换和页面加载时的简历自动下载。
- 简历附件改为明确的“预览”和“下载”手动操作，PDF 在页面内嵌预览。
- 候选人快照过期时提示重新拉取新邮件，避免直接显示英文 `candidate not found`。

## [0.1.0-alpha.4] - 2026-09-06

### Added

- 招聘页新增“检测环境”入口，可从网页检查 provider 容器内 `qtrecurit` CLI 与 HR 邮箱认证态是否就绪。
- 新增 provider 状态提示条，向使用者展示可执行/不可用原因，避免同事上线后误以为浏览器会读取本地 CLI。

## [0.1.0-alpha.3] - 2026-09-05

### Fixed

- Studio 发布构建注入 `QTCLOUD_HUMAN_API_BASE_URL`，避免上线后招聘页仍处于 provider API 未配置状态。
- Studio 发布流水线在缺少 provider API 地址时直接失败，防止静态页面和后端发布脱节。
